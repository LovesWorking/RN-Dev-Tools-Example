# Repository Guidelines

## Project Structure & Module Organization

- `app/`: Expo Router entry points and screens (e.g., `index.tsx`, `_layout.tsx`).
- `components/`: Reusable UI and demo components; snapshots in `components/__tests__/`.
- `src/`: Shared modules (`components/`, `hooks/`, `utils/`, `storage/`, `data/`).
- `rn-better-dev-tools/`: In-repo dev tools UI and shared utilities.
- `assets/`: Images, fonts, static assets. Native folders: `ios/`, `android/` (generated by `prebuild`).

## Build, Test, and Development Commands

- `npm start` / `npm run dev`: Start Expo dev server (web via `--web`).
- `npm run ios` / `npm run android`: Run on iOS Simulator / Android emulator.
- `npm run prebuild`: Regenerate native projects (cleans by default here).
- `npm run lint`: Lint with Expo/ESLint config.
- `npm test`: Run Jest (jest-expo preset, watch mode).
- `npm run screenshot[:ios|:android]`: Save simulator/emulator screenshots to `./screenshots/`.
- Utilities: `scripts/reset-project.js`, and "nuke" scripts (use with care) to fully clean installs and native folders.

## Coding Style & Naming Conventions

- TypeScript strict mode; JSX runtime `react-jsx`.
- ESLint: `eslint-config-expo` base with repo-specific overrides.
- Indentation: 2 spaces; single quotes; trailing commas where allowed.
- Names: Components `PascalCase` (`FloatingPokemonCard.tsx`), hooks `useCamelCase.ts`, variables `camelCase`, constants `SCREAMING_SNAKE_CASE` when global.
- Paths: `@/*` base alias; keep imports relative within a package when clearer.

## Testing Guidelines

- Framework: `jest-expo` with React Testing Library patterns acceptable.
- Location: Co-locate tests or use `__tests__/` directories.
- Naming: `*.test.ts`/`*.test.tsx`; snapshots in `__snapshots__/`.
- Run: `npm test` (CI-friendly), keep tests deterministic; avoid relying on network or timers.

## Commit & Pull Request Guidelines

- Commits: Use present tense, imperative, and scope when helpful.
  - Example: `Refactor: extract Badge and SectionHeader`, `Fix: query actions re-render`
- PRs: Include clear description, rationale, and before/after screenshots for UI. Link issues, list breaking changes, and update docs (README, this file) when behavior changes.
- Quality gates: `npm run lint` and `npm test` pass; ensure app launches via `npm start`.

## Security & Configuration Tips

- Environment: Use `EXPO_PUBLIC_*` for client-visible vars. Do not commit secrets; prefer `.env.local`.
- Avoid adding production-only code to dev tools; the tools are disabled in production builds by default.
